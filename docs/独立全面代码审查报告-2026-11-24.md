## 一、严重 / 高风险发现（实测坐实）

### R3-H1 0007 派语重映射触发 UNIQUE 冲突，多谱老库升级失败
- **位置**：`shared/schema/0007_single_book.sql:41`；约束源 `0001_init.sql:187`
- **实测**：按 0001 建 `generation_poem` 表，插入 `('lineage','L1',1)` 与 `('lineage','L2',1)` 两条后执行 `UPDATE ... SET owner_id='book' WHERE owner_type='lineage'`：
  ```
  CONFIRMED CONFLICT: UNIQUE constraint failed: generation_poem.owner_type, generation_poem.owner_id, generation_poem.seq
  ```
- **触发**：老库存在 ≥2 条 lineage 且各有派语（seq 通常都从 1 起，很常见）。
- **影响**：迁移事务回滚 → `Database::open` 返回 Internal，**该库彻底无法打开**；即使不冲突，多谱派语也静默合并/丢弃。两个独立代理同时发现此问题。
- **建议**：UPDATE 前按原 owner_id 分段重排 seq（保留全部派语），或明确"只保留首谱、其余转存"策略；补多谱老库升级集成测试。

### R3-H2 SQLite 走 FetchContent 联网下载，与"无联网组件"定位冲突
- **位置**：`third_party/sqlite3/CMakeLists.txt:14-24`（`URL https://sqlite.org/...`）
- **触发**：离线/内网构建，或 sqlite.org 不可达/TLS 抖动时 configure。
- **影响**：所有构建在 configure 阶段失败；`gui/CMakeLists.txt` 自身注释已记载"FetchContent 在 configure 期下载，一失败整个 configure 挂死"，但 sqlite3 仍用该方式。
- **建议**：将 amalgamation 的 `sqlite3.c/.h` vendor 入库（两个文件），或提供本地源码回退分支。

### R3-H3 世系表行内编辑状态在换库后未清理（跨库写错数据风险）
- **位置**：`gui/include/genealogy/gui/panels/person_table.hpp:79-83` + `gui/src/panels/person_table_state.cpp:52-62`
- **核实**：`on_database_closed()` 只清 `rows_/loaded_db_path_/loaded_`，**未调用 `cancel_edit()`**；`has_cached_data()` 因 `editing()` 仍返回 true。
- **触发**：双击行进入编辑 → 关库或换库 → 编辑区仍显示旧库人物，点"保存"用旧 id 在新库执行 `update_person`。
- **影响**：破坏换库清理不变量；存在跨库写错数据风险。
- **建议**：`on_database_closed()` 首行加 `cancel_edit();`。

### R3-H4 新建支派/地点失败后 draft 卡在编辑态
- **位置**：`gui/src/panels/branch_panel_state.cpp:33-40`、`place_panel_state.cpp:51-55`
- **核实**：`if (is_new) draft_.id = generate_ulid();` 在 `create_*` **之前**执行；创建失败时 id 已非空，`editing()` 变 true，界面切到"保存修改"，下次走 `update_*` 但 id 在库中不存在 → 再次失败。
- **触发**：名称校验失败、唯一性冲突、DB I/O 错误等任一失败路径。
- **影响**：用户流程卡死，必须显式点"新建空白"才能重试。
- **建议**：失败时 `draft_.id.clear()`，或把 id 生成移到成功分支。
