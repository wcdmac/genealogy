# GUI 全面规划：家谱录入·修改·查阅·管理·排版（2026-11-23）

## 结论

**当前 GUI 有 6 个面板但缺"以人物为中心的操作闭环"**：能看、能改既有、能检索、能校验，但**不能新建人物、不能建立关系、没有排版入口、没有导航快捷键**。调研国内外 20+ 款家谱软件后，规划为「一个焦点人物 + 五条工作流 + 十一个面板」，分三批落地。

**合规**：只借鉴公开资料描述的功能与交互思想（如 Gramps 的关系快捷按钮、Heredis 的智能预填、Legacy 的分级警示、FamilySearch 的并排合并），不取任何源码、UI 布局、图标或文案。

## 一、调研结论（博采众家之长）

### 被反复验证"高效"的交互（高优先级借鉴）

| Gramps | 就地确认即保存、切换视图自动退出编辑态 | 人物卡保存后自动刷新关联面板 |

| Heredis | 智能预填整户表单、一键加直系亲属 | 新建人物按焦点自动预填姓氏/籍贯 |

### 被吐槽"难用"的（明确规避）

- Ancestry：按钮/链接迷宫、提示过载、重复合并难撤销 → **本项目每屏只给相关命令、提示可分级关闭**。
- Gramps：术语严谨但学习曲线陡 → **本项目用中式称谓（父亲/配偶/世系）而非西方术语**。
- MyHeritage：西式"家庭树"体例与中式族谱不匹配 → **本项目优先欧式/苏式/牒记式/世系表**。

### 国内产品观察

中华族谱网/修谱王/族谱王/有谱小程序等共同点：强调**世系图 + 世系表双视图**、**支派管理**、**字辈派语**、**一键成书**。本项目 core 已有派语/支派/六种世系图 + P0/P1/P2 出版管线——**GUI 缺的是把这些能力串成工作流**。

## 二、当前状态与差距

现有 6 面板：人物卡、人物表格、检索、关系、树、校验。已有：打开库、面板开关、字体缩放、高对比度、人物卡修改保存、跨面板焦点联动、校验异步。

**差距（本轮要补）**：
1. 无「新建人物」——冷启动无法在 GUI 录人
2. 无「关系建立」——父子/配偶只能靠 GEDCOM 导入
3. 无「排版入口」——P0/P1/P2 出版能力只对 CLI 可用
4. 无「导航快捷键」——大树里移动全靠鼠标
5. 无「批量/表格编辑」——大量录入必须逐个开卡
6. 无「支派/字辈管理面板」——core 有服务但 GUI 无入口

## 三、信息架构：一个焦点 + 五条工作流

```
                 ┌─────────────────────────┐
                 │  焦点人物（AppState）    │
                 │  selected_person_id     │
                 └───────────┬─────────────┘
                             │ 联动
   ┌──────────────┬──────────┼──────────┬──────────────┐
   │              │          │          │              │
 录入流          修改流     查阅流     管理流        排版流
 NewPerson     PersonCard   Tree       Validation    BookExport
 RelationQuick  TableInline Search     Branch         ChartExport
 Import         Merge       Timeline   Place          LayoutExport
```

焦点人物是唯一状态源（已有 `selected_person_id`），所有面板经 `AppState` 联动，不互持引用（延续现有架构原则）。

## 四、五个工作流详解

### 1. 录入流（最高优先）

- **新建人物面板**：姓氏从焦点人物/默认宗族预填；姓名、字、号、性别、生卒日期（复用 `GenealogyDate` 年号识别）、籍贯；确认后成为新焦点。
- **关系快捷按钮**（人物卡内）：父亲 / 母亲 / 配偶 / 子女 四个按钮，点击弹「链接已有（检索框）」或「新建（最简表单）」。复用 `PersonService::create`、`UnionService`。
- **批量导入**：GEDCOM 已有 CLI，GUI 加「导入」菜单项调用同一 core 用例。

### 2. 修改流

- 人物卡就地编辑 + 保存（已有，补自动刷新联动面板）。
- 表格双击行进入行内编辑（姓名/生卒/性别等常用字段）。
- 校验结果分级呈现：错误/警告/提示三色，右键「忽略此条」「忽略此类」（借鉴 Legacy）。
- 重复人物合并向导（后续批）：并排对照 + 关系迁移。

### 3. 查阅流

- 树面板：键盘焦点移动（方向键在父子/配偶间切换）、滚轮缩放、拖拽平移、世代分色。
- 表格：点击列头排序、双击编辑、焦点行高亮。
- 检索：结果行内「定位到树」「打开人物卡」双入口。
- 关系面板：保留现有计算，补「复制称谓」按钮。
- 时间线（后续批）：按年月日排列事件。

### 4. 管理流

- 支派面板：列出支派、新增/编辑、成员归属调整（复用 `BranchService`）。
- 字辈派语面板：查看/编辑派语联句、校验世代用字（复用 `GenerationPoemService`）。
- 地点面板：地点库增删改（复用 `PlaceService`）。
- 备份/恢复：菜单项调用已有 `backup`/`restore` core 逻辑（VACUUM INTO 快照）。

### 5. 排版流

- **排版面板**（新）：三个页签
  - 世系图：`io export chart` 六种体例预览（复用 core SVG 生成器）
  - 谱书：`io export book` 三种版式 + `--use-layout` 古籍版式（复用 P0/P2）
  - 古籍版式：`io export layout` 标记文本 + 预设（复用 P2）
- 参数区：纸张、体例、预设、字号（`--body-size`）；「导出 SVG/PDF」按钮写文件并弹状态栏。
- 预览：用 ImGui 的 `Image` 显示生成的 SVG 需光栅化；首版先「生成到文件 + 系统默认程序打开」，避免引入 SVG 渲染依赖。

## 六、与 core 的边界（ADR-1）

- GUI 只经 `DbSession` 拿服务，不直连仓储——新面板一律遵守。
- 排版预览复用 core 的 `render_layout_page` / `render_chart_svg` / `render_book_html`，**不在 GUI 重写排版逻辑**。
- 重状态机面板继续拆 `*_state.cpp`（无 ImGui 依赖、可无头测试），延续现有 debt 偿还模式。
