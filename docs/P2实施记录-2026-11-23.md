# P2 实施记录：标记语法与古籍版式全要素（2026-11-23）

## 结论

**P2 两项全部落地**：① 自有标记语法解析器（`〔卷〕〔章〕〔节〕〔注〕〔批〕〔耳〕〔标〕〔圈〕〔点〕〔页〕〔indent:N〕`）；② 古籍版式全要素参数化（版心/鱼尾/象鼻/栏线/书耳/界行/天头地脚/夹注/圈点/专名线）。CLI `genea io export layout` 接通。core 152 用例 / 993,478 断言。全门禁通过，SVG 经 Edge 无头打印验证。

## 一、标记语法（`core/io/markup.cpp`）

符号集为本项目自研（中文全角 `〔〕`，公版标点），**不采用**墨韵/易籍/亦句/GujiStudio 的具体符号——只借鉴「标记与正文同处一地、改字即重排」的功能思想。

- 线性单遍解析，无复杂状态机：配对标记用 `find("〔/name〕")` 直接定位内容。
- 未识别标记原样保留为正文、不吞内容；未闭合配对告警并保留余下文本。
- `indent:N` 非法值告警。

**开发中踩的真实坑**：`〔`/`〕` 是 UTF-8 三字节，`substr(open+1, ...)` 把首字节切掉，导致 `indent:N` 变 `dent:N`、所有中文标记失配。改为 `open+3` / `close+3` 后全绿——与历法 `find('年')` 窄化、P1 逐字节哈希同源，已写入注释。

## 二、古籍版式全要素（`core/io/layout_svg.cpp`）

参数外置在 `shared/layout/*.json`，构建时经 `EmbedText.cmake` 嵌入二进制——改版式改 JSON，不改 C++。

| 要素 | guji_classic | plain_modern |
|---|---|---|
| 栏线（外框/内框、单双线） | ✓ 双线 | 无 |
| 界行 | ✓ | 无 |
| 版心（书名/卷次/页码） | ✓ | ✓ |
| 鱼尾 | ✓ 自绘三角 | 无 |
| 象鼻 | ✓ 上下横线 | 无 |
| 书耳 | ✓ 左上耳框 | 无 |
| 夹注/眉批/专名线/圈点 | ✓ | 部分 |

图形 SVG 几何**自行设计**（据古籍版本学通识的公版形制），不描摹任何商业软件素材。逐字竖排按 UTF-8 码点切分——按单 `char` 切会产生非法 UTF-8（实测导出文件解码失败），已修。

## 三、CLI 与验证

`genea io export layout --source <file> --preset <id> --title --volume --out`：按 `〔页〕` 分页，多页输出 `foo-pN.svg`。

验证：
- core 152 用例 / 993,478 断言全过（新增 `test_markup.cpp` 5 例、`test_layout_svg.cpp` 3 例）。

- 全门禁：编译、GUI/CLI 测试、e2e、演练、许可、GUI 无头。

## 四、边界

- 逐字竖排目前是"一个 `<text>` 一个字"的 SVG 元素（单页 50 字 50 个元素），万字页 SVG 会较大；未做字形合并优化。
- 夹注"跨页续排"在预设 JSON 中有参数，但当前渲染是同页小字，跨页续排逻辑未实现（调研中墨韵的独有能力，属后续）。
- 版式要素的视觉形制是公版通识的简化表达，不是专业古籍复刻级精度。
- 本记录对应改动尚未提交。
