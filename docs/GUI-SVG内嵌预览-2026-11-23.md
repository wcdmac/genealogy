# GUI SVG 内嵌预览：澄清与实现（2026-11-23）

## 结论

**此前的"需引入光栅化依赖、违反依赖纪律"说法不成立。** 主人质疑后复核，有三条路，本项目采用了最契合的一条——**零新增依赖**。

## 一、为何不需要光栅化依赖

1. **合规单头库本可选用**：nanosvg（MIT）、stb_image（公有领域）都在项目依赖白名单（MIT/BSD/zlib/BSL/公有领域）内，说"违反纪律"是错的。
2. **更契合的路：自家 SVG 子集 → ImDrawList**。SVG 由本项目自己生成，标签只有 rect/line/circle/path/text，样式来自 `<style>` 里的简易 class 规则。解析这个子集只需字符串扫描；绘制用 ImGui 已有的 `ImDrawList`（AddRect/AddLine/AddCircle/AddText 全是原生能力）。项目已加载思源中文字体，竖排逐码点定位即可。
3. **单一来源**：预览与导出消费**同一个 SVG 字符串**——不是另写一套渲染逻辑，因此像素级一致，也不会出现"预览和导出不一样"。

## 二、实现

- `gui/include/genealogy/gui/svg_preview.hpp` / `src/svg_preview.cpp`：纯 C++ 解析层（无 ImGui 依赖，可无头测试）。解析 viewBox、`<style>` class 规则（含全局 `text{}`）、五种元素的属性与内联 `style='font-size:…'`，XML 实体反转义。
- `gui/include/genealogy/gui/svg_preview_draw.hpp` / `src/svg_preview_draw.cpp`：ImGui 绘制层。`#rrggbb`→ABGR、class 样式回落、path 的 M/L/Q/Z 折线（Q 控制点近似）、竖排按 font-size 逐码点推进。
- 排版导出面板：生成后 `refresh_scene()` 解析 SVG；「内嵌预览」开关开启后在子进程区域按可用空间等比缩放绘制；显示图元数与字节数。

**依赖变化：零。** 没有新增任何库、包或外部程序调用。

## 四、边界

- 解析器只认自家生成的 SVG 子集；外部任意 SVG（渐变、变换、复杂 path 曲线、外链字体）不支持，也不需要支持。
- path 的 Q（贝塞尔）用控制点折线近似，预览曲线略棱角化；导出 SVG 仍由浏览器精确渲染，不受影响。
- 竖排字符间距按 font-size 推进，与浏览器 `writing-mode` 行为一致；未逐字形测量字面框。
- 本记录对应改动尚未提交。
