## 2. 本轮新发现

共 **33 条候选**，交叉验证后确认 **24 条**（高 6、中 11、低 7）。以下按主题归类，完整证据见各子节。

### 2.1 高危（6 项）

**新-1｜支派树递归无环防护／深度上限** `server/src/routes_entities.cpp:458-482` + `core/src/service/branch_service.cpp:28-39`
`emit` 递归无 visited；`BranchService::validate` 只校验父房存在 + 同宗族，不拒绝自指或环。A→B、B→A 后 `GET /branches/{id}/tree` 栈溢出，editor 角色可稳定触发。H7 的防护只加在 core 的 `lineage/tree.cpp`，server 侧另写一套递归属盲区。改进：`emit` 加 visited + 深度上限；validate 加祖先链环检测。

**新-2｜`expand` 子资源未脱敏** `server/src/routes_persons.cpp:284-285,313-370`
主对象 `body` 调用 `sanitize_person`，随后追加的 events/migrations/unions/names 直接 `to_json` 塞入。viewer（raw_privacy=false）用 `GET /persons/{id}?expand=events,migrations` 可读到刚被抹掉的在世者精确生卒、地点、描述。改进：对子资源逐一脱敏，或组装完统一递归脱敏。

**新-C1｜restore 未校验快照完整性** `cli/src/cmd_backup.cpp:187-224,251-288`
H2 只验证"目录存在 + 有任意 .db"，未按原要求验证快照可读性/SQLite 完整性。损坏或截断的 .db 会被复制成新库并打印"恢复完成"，`copy_file` 成功连 H3 回滚都不触发。改进：动库前 `sqlite3_open_v2(READONLY)` + `PRAGMA quick_check`。

**新-C2｜rollback_moved 在磁盘满时失效** `cli/src/cmd_backup.cpp:234-250,279-288`
`copy_file` 失败可能在 `db_path` 留下 0 字节/截断残留；Windows `fs::rename` 目标存在即失败，回滚只打印"请手动移回"并返回 1，用户库两头空。改进：回滚前清理残留目标。

**新-W1｜协议相对 URL 绕过外域确认** `clients/web/src/App.tsx:39-64`、`client.ts:127-131`
`isConnectableAddress` 与 `isSameHost` 都用 `startsWith("/")` 判同源。输入 `//evil.com/api/v1` 两者均返回 true，confirm 被短路；`new URL(this.baseUrl + path, origin)` 解析为外部主机，口令静默外发。改进：`startsWith("/") && !startsWith("//") && !startsWith("/\\")`，或统一解析后比 hostname。

**新-5｜幂等重放绕过脱敏** `server/src/routes_persons.cpp:250-255`、`idempotency.cpp:66-78`
缓存写入的是脱敏前的完整 JSON，重放时直接回缓存体不再脱敏。editor/steward（raw_privacy=false）创建 private 人物后，用同一 Idempotency-Key 重放可拿到原始体。改进：缓存脱敏后的响应体，或重放出口统一脱敏。

### 2.2 中危（11 项）

## 4. 扩展改进方向

1. **结构性问题：同一算法多处手写**。H7 环防护只加在 core，server 又写一份支派递归。建议把"树展开/环检测/深度上限"收敛为 core 的唯一入口，server/CLI/GUI 只消费。
2. **脱敏成为横切关注点**。本轮连续发现 expand 与幂等重放两处绕过，说明逐 handler 调用 helper 不可持续。建议在响应出口做统一后处理（按 identity 递归裁剪），而非各路径自行调用。
3. **分页协议统一**。`/search` 游标未接入、四端点 has_more 恒 false，反映 Page 信封缺乏共享实现。建议抽一个 `paginate(filter, mapper)` 模板，避免每端点复制 +1 判据。
4. **测试策略：断言"行为"而非"命令跑通"**。e2e 73/73 未发现 `--events-per-person` 无效、裸 bench 不可达、损坏快照可恢复——都是"命令成功但语义错"。建议新增断言库：每个 CLI 参数至少一条"参数确实生效"断言。
5. **GUI 数据装配可测性**。ROADMAP 已登记"面板装配抽离 ImGui TU"暂缓；本轮 C3/C4/C5 全在面板状态机，正是该债务的直接后果。建议提前偿还，把 dirty/缓存失效/深度重建纳入无头单测。
6. **依赖治理扩展到前端**。许可白名单只覆盖 C++ 依赖，与 README 的全局承诺不符。建议生成 SBOM 并把 npm 依赖纳入 CI 卡点。
7. **契约治理**。修复引入的新状态码（415/429/501/503）未回写 spec，形成"实现先行、规范滞后"。建议在 CI 加"响应状态码集合 ⊆ spec 声明集合"的检查。
