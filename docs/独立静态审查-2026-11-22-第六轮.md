## 一、高（4）

### 【高-1】派语服务 set_poem 归属校验被架空，且存在损坏的死语句
- **位置**：`core/src/service/generation_poem_service.cpp:26-32`
- **问题**：`if (owner == PoemOwner::Lineage) { auto b = books_.get(); }` 中 `b` 被丢弃、无校验；第 29 行 `      } else {` 缩进损坏。注释声称"归属必须存在"，实现却完全没检查。对比 `check_consistency` 的 Lineage 分支是刻意留空，二者不一致。
- **触发场景**：以 Lineage 归属录入派语；或开启 `-Wall -Wextra`（`b` 未使用告警）。
- **影响**：派语写库的归属前置校验对 Lineage 失效；编辑残留损害可读性，是上一轮修 bug 时留下的新缺陷。
- **建议**：与 `check_consistency` 对齐——若单谱单库恒有 book 行，直接删除无用调用并修正缩进；若需校验则 `if (!b) return b.error();`。
- **证据**：见位置代码。

### 【高-2】GUI 后台 worker 线程无异常兜底，异常逃逸即 std::terminate
- **位置**：`gui/src/panels/tree_panel_state.cpp:70`、`:145`（validation）、`cli/src/cmd_io.cpp:996`（bench 线程）
- **问题**：三个线程入口均无 try/catch。`main`/`run()` 的 try 块只覆盖调用线程，无法跨越线程边界。
- **触发场景**：20 万人物装载时 `bad_alloc`；校验线程抛异常；bench 并发写极端条件抛异常。
- **影响**：GUI/CLI 进程闪退，无错误提示、无回滚，`running_` 可能残留 true 导致后续操作卡死。
- **建议**：每个 lambda 最外层加 `try/catch`，异常文本写入 pending_error_，并确保 `running_=false`、代际作废。
- **证据**：`worker_ = std::thread([...]{ ... });` 内无 try 块。

### 【高-3】历法测试夹具生成器依赖 gitignore 数据，新 clone 重跑静默假绿
- **位置**：`tools/gen_calendar/emit_tests.js:15-18`；`core/tests/test_calendar.cpp:202`；`.gitignore:35`
- **问题**：干支夹具来源是 `.data/pmo/pmo_truth.jsonl`（4.9MB，被 gitignore）。文件不存在时 `truth=[]` 静默降级，生成 `kDayGanzhiCount=0`，测试循环零次仍通过；`verify.js` 对同一文件直接 readFileSync，缺失时崩溃。
- **触发场景**：新开发者 clone 后按 README 重跑生成链路。
- **影响**：3024 条官方逐日干支回归断言全部消失而测试仍绿——典型假绿，历法正确性防线失效。
- **建议**：把精简校验集（如抽样 200 条）入库为 fixture；truth 缺失时 throw 而非降级；`verify.js` 加 existsSync 前置检查。
- **证据**：`const truth = fs.existsSync(truthPath) ? ... : [];`

### 【高-4】全局 --help 吞掉子命令 help，上一轮新增的 help 分支不可达
- **位置**：`cli/src/main.cpp:994`；`cmd_source.cpp:60`、`cmd_document.cpp:52`、`cmd_poem.cpp:77`
- **问题**：cxxopts 全局解析器识别任意位置的 `--help`，`run()` 先判 `g.count("help")>0` 就打印全局帮助并 return 0，命令永远分派不到。实测 `genea source --help` 输出全局帮助。
- **影响**：上一轮为 source/document 补的 help 分支全是死代码；用户看不到子命令专属用法。
- **建议**：全局 help 判定改为仅当 `unmatched.empty()` 时生效，或从全局解析器移除 help 选项。
- **证据**：实测输出为全局帮助（见验证记录）。

## 五、被剔除的误报（摘要）

- **行尾约定冲突**：工作树 CRLF 是 Windows autocrlf 检出效果，`git show HEAD:<file>` 证实入库均为 LF，符合 `.gitattributes`。CI 用 `bash file` 方式执行不受影响。
- **e2e 临时目录不清理**：`.data/testdata` 被 gitignore，且脚本开头会自清，属有意保留调试产物。
- **BulkLoader 嵌套提交隐患**：`sqlite_util.hpp` 已文档化"BulkLoader 须在最外层"前提，属调用方契约，不计缺陷。
- **stdout 随机截断**：基线专项审查结论仍有效（无确切代码根因，dump() 生命周期/线程/format 均干净），本轮未重复计入。
