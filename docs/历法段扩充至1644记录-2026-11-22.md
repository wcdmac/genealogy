# 历法事实段扩充至 1644（2026-11-22）

## 结论

**大统历史实段从 1368–1582 扩至 1368–1644（277 年），节气与天文推算起点同步从 1583 提至 1645。** 扩充修正了 62 年中 5 处与天文推算不符的史实（1600/1609 正月初一差 1 日，1588/1599/1600/1608/1609 月长或闰位不同）。全量验证通过。

## 为什么扩到 1644 而非 1899

历法史分界：1645 年清《时宪书》颁行，废平气平朔、改定气定朔——与现行农历及 GB/T 33661-2017 推算**模型同源**。因此：
- 1368–1644（明大统历行用期）：旧历法模型，须用史实数据，否则有 1 日级偏差；
- 1645–3000：现代推算同源，生成器记录的 22 处历书差异中仅 4 处在 1645–1727（过渡期），1728 年后零差异。

## 数据合规处置

沿用第五轮 GPL 清除的既定口径：**只提取历法事实数值**（各月初一的绝对日序），不复制上游任何代码或表达。依据《著作权法》第五条第（三）项，历法不受著作权保护。

- 来源：git 历史中 `d3b9876^` 的上游数据文件（`calendarData.js`，实际覆盖公元前 104–公元 2200 年，共 2306 行），一次性提取 1583–1644 共 62 年的 `year/first_day/month_count/leap_after/len_mask` 五个字段。
  - 更正：此前按上游 README 标称写作"公元前 722–2200"，经逐行核对数据文件实际起点为 -105（即公元前 104，无公元 0 年）；上游对公元前 104 年以前另走 `ancientCalendars.js` 天文推算，非同一事实表。
- 固化到新文件 `tools/gen_calendar/fixtures/ming_datong_gregorian_facts.json`（与 1368–1582 的 `ming_datong_facts.json` 分开，因**历法口径不同**）。
- 一次性提取脚本仅存于 `.data/`，未入库；仓库中无 GPL 代码或来源声明残留。
