# GUI P1 实施记录：管理流闭环（2026-11-23）

## 结论

**GUI P1 五项全部落地**：表格行内编辑、支派管理、地点管理、字辈派语、备份恢复。GUI 无头测试 **23 用例 / 250 断言全过**，全门禁通过。规划文档 `docs/GUI全面规划-2026-11-23.md` 的 P1 清单全部兑现。

## 一、表格行内编辑

- 世系表姓名列**双击**进入编辑态（单击仍是焦点联动）；表格下方出现编辑区：姓/名/字/性别/世代/行几。
- 走 `PersonService::update_person` 的 rev 乐观锁；保存后自动重载入表格并设为焦点。
- 状态机 `person_table_state.cpp` 无 ImGui 依赖；新增无头入口 `reload_for_test` / `begin_edit` / `save_edit`。

规范复用：姓名列原来单击即切焦点，现在双击进编辑——延续 Gramps/RootsMagic 的"双击进编辑"。

## 二、支派与地点管理面板

- `DbSession` 已暴露 `branches()` / `places()`，本轮补 `poems()`。
- **支派面板**：列表（名称/父房/备注）+ 新建/选中更新；`BranchService` CRUD；乐观锁由服务层 rev 保证。
- **地点面板**：列表 + 新建/更新（今属地、历史沿革、经纬度、备注）；经纬度范围校验（纬度 -90..90、经度 -180..180），非法值拒绝而非静默丢。
- 两面板都提供无头编辑入口（`edit_*` + `sync_draft`），与渲染控件同一落点——测试无需 ImGui 即可驱动。

## 三、字辈派语面板

- 谱级（owner_id=`book`）/支派级切换；联句原文录入 → `GenerationPoemService::set_poem`（引擎只取汉字）。
- 读取已有派语按辈序列出；「一致性校验」调用 `check_consistency`，冲突以红字呈现（人名 + 差异说明）。
- 实测「天地玄黄，宇宙洪荒」→ 8 条目、首字"天"末字"荒"，校验无冲突。

## 四、备份恢复入口（核心下沉）

- **下沉 core**：新增 `core/io/backup_service.hpp/cpp`，提供 `backup_timestamp()` / `snapshot_database()`（VACUUM INTO）/ `verify_snapshot()` / `restore_database()`。
- **CLI 改为调用 core 的快照函数**（行为不变，备份演练 77 项全过），消除 CLI 与 GUI 两份逻辑漂移。
- GUI 备份面板：备份目录选择、立即备份；恢复默认**拒绝覆盖已存在库**，勾选确认后旧库连同 `-wal`/`-shm` 移为 `.bak-<时间戳>`，任一步失败回滚。
- **Windows 文件锁的真实处理**：恢复前必须 `session.close()` 释放连接（否则 `fs::rename` 报"进程无法访问文件"），恢复后 `session.open()` 重开——`restore_and_reopen()` 封装此序列。
- GUI 面板仅处理主库；附件目录需另行备份（界面已提示）。

开发中踩坑：新建 vs 更新须在生成 id **之前**判定；`ImGui::SeparatorText` 只接一个参数；ImGui 原生 `InputText` 不接 `std::string`（用项目 `widgets.hpp` 包装）；新面板 TU 须同时加入 `genealogy-gui` 与 `genealogy-gui-tests` 两个 target；恢复前不关会话会被 Windows 文件锁挡住。

## 六、边界

- 备份恢复只处理主库，附件目录未随 GUI 面板走（CLI 的 `db backup/restore` 仍含附件，功能更完整）。
- 恢复后其他已打开同一库的程序需重启才能看到新数据。
- 表格行内编辑只覆盖常用字段（姓/名/字/性别/世代/行几），全字段编辑仍走人物卡。
- 支派/地点面板没有删除按钮（core 有 `remove_*`，但删除涉及引用完整性确认，留待后续）。
