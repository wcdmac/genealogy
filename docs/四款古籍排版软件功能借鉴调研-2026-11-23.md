# 四款古籍排版软件功能借鉴调研（2026-11-23）

## 结论

**四款软件值得借鉴的功能集中在「古籍版式要素参数化」与「注释/校勘的排版表达」两处，这正是本项目 P0 出版的空白。** 最值得借鉴的三项（按优先级）：① **标记语法驱动排版**（易籍/GujiStudio，改字即重排）；② **古籍版式要素体系**（版心/鱼尾/象鼻/栏线/书耳，四款共性）；③ **造字与缺字检查闭环**（墨韵，与本项目"全库自带字体"策略互补）。

**合规前提**：只借鉴**功能思想与版式规则**（思想/事实不受著作权保护），不复制任何源码、可执行程序、UI 布局、图标、文档文案或独有视觉设计。四款软件的字体/鱼尾纹样等**具体美术表达**同样不复制——自行按公版古籍形制重新绘制。

## 二、值得借鉴的功能（按优先级）

### P1 — 标记语法驱动排版（最高杠杆）

易籍用 `#`/`$`/`|...|`/`%`，GujiStudio 用 `{}`/`[]`/`^拼音^` 在**纯文本里嵌入排版指令**，正文改动后一键重排，不必手工维护版面。项目当前的 HTML 出版是"一次性生成"，改正文需重新输命令——若引入一套**自有标记语法**（例如 `【注】…` 表夹注、`〈句〉` 表圈点、`#` 表标题），则：
- 老谱原文可直接作为源文件录入，排版指令与正文同处一地；
- CLI/GUI 共用同一解析器（放 core，符合 ADR-1）；
- 与已有 `GenealogyDate::era_year()` 的老谱原文识别天然衔接。

**借鉴边界**：借鉴"标记语法驱动重排"这一**思想**，不采用四款软件的具体符号定义——自行设计一套符号与语义，避免表达雷同。

### P2 — 古籍版式要素体系

版心（书名/卷次/页码）、鱼尾、象鼻、栏线、书耳是古籍排版的**公版形制事实**（非任何软件独创），可据古籍版本学通识自行实现：
- 版心分区参数化（宽度/高度/文字）；
- 鱼尾用 SVG 自绘（自行设计形制，不描摹某款的十款矢量鱼尾）；
- 栏线单/双/无、书耳页级覆盖。

项目已有"规则外置 JSON"机制（`shared/rules/`），版式参数同样可外置为 `shared/layout/` 预设，改 JSON 不改代码。

### P3 — 双行夹注与圈点句读

墨韵的夹注"列内排不下自动移至下页并跨页续排"与 GujiStudio 的"现代标点在渲染期映射为矢量句读、源文件保留现代标点"是两项高价值设计：
- 夹注跨页续排 → 项目 HTML 出版可借鉴其**分页续排规则**（思想）；
- 标点→句读映射 → 可加 `--punctuation-mode {modern,circle,none}` 参数，源文件存现代标点、出版时映射为圈点，无损切换。

### 值得关注但非当前优先

- **造字与缺字检查**（墨韵）：项目已全库自带字体，造字是"最后 1% 生僻字"方案。可作为 P2 阶段"生僻字回退链"的补充，但造字工具复杂度高（部件拼合→TTF 生成），优先级低于前三项。
- **底本对照校勘**（墨韵）：与项目"证据链/citation"主线相关，但那是图像钉住与 PDF 页码同步，属独立功能域。
- **做旧/印刷出血**：偏美术效果，家谱印刷可用但非核心。
- **模板/工程文件**：项目 CLI 参数 + SQLite 已覆盖"工程状态"需求，无需另造 `.gtext` 类文件。

## 三、版权边界（合规借鉴的操作定义）

| 可借鉴 | 不可复制 |
|---|---|
| 功能需求本身（"支持夹注跨页续排"） | 源码、算法实现细节的表达式 |
| 公版古籍形制（鱼尾/象鼻/版心/线装） | 某软件独有的鱼尾矢量图、纹样、图标 |
| 通用交互范式（标记语法驱动、所见即所得） | 具体的符号集、快捷键组合、UI 布局截图 |
| 公开文档描述的功能行为 | 帮助文档文案、宣传语、截图 |

注意 GujiStudio 为 **AGPL-3.0 开源**——即使开源也不得把其代码并入本项目（AGPL 与闭源商用冲突）。易籍自述开源但未核实具体许可，同样不取源码。四款均只作"功能需求来源"，实现全部自研。

1. 先做 P1：为核心新增自有标记语法解析器 + `io export book --source <txt>`，实现"改字即重排"。

3. 最后评估 P3 夹注续排与标点映射。
