# 修谱工作流

> 从「族老口述 + 一册老谱」到「一部能交付、能校验、能备份的谱」。
> 本工作流面向实际修谱场景设计；每个步骤都标注了对应的软件操作。

## 阶段 0：筹备（不动软件）

| 事项 | 要点 |
|---|---|
| 收齐材料 | 老谱（刻本/抄本/影印）、墓碑照片、口述记录、户籍资料 |
| 访谈族老 | 按「始祖 → 各支派 → 各家」逐层问；**边问边记疑点**，不现场拍板 |
| 定宗族要素 | 姓氏、堂号、郡望、始迁祖与始迁时间、派语（字辈联句） |
| 定工作目录 | 老谱扫描件、访谈记录、备份目录分开存放；备份目录另置一盘 |

> **派语是全谱的骨架**，先问清楚。派语每代一字（「德茂光先祖，文章振万邦」），
> 后面每个人的世代归属都靠它校验。

## 阶段 1：建档（宗族骨架）

```bash
genea db init --db family.db
genea lineage add --db family.db --name "中湘陈氏六修族谱" --surname 陈 --commandery 颍川 --hall 德星堂
genea place add --db family.db --name 中湘 --type county --modern "湖南省湘潭县"
genea poem set --db family.db --lineage <ID> --text "德茂光先祖，文章振万邦"
```

- **宗族先于人物**：一切归属的根。
- **地点先于迁徙/事件**：历史地名登记（含现代政区对照与经纬度，供迁徙地图）。
- **派语立即录入**：后面每录一代人都能拿它校对。

## 阶段 2：人物录入（先直系后旁支）

```bash
genea person add --db family.db --family-name 陈 --given-name 文远 --gender male \
  --birth "同治三年四月初四" --father <父ID> --generation 3
```

顺序建议：**始祖 → 二世 → 历世直系 → 各支派 → 旁支配偶**。

- 老谱日期**照录原文**（`同治三年四月初四`），系统自动识别年号并换算公历、
  推年干支；解不出的只留原文记损失，不编。
- 父母 ID 用列表里复制（`person list --format json`）。
- 口述存疑的（生年约数、排行不确定）先按最低置信录入，`note` 里记疑点，
  不要为了「好看」编圆。

## 阶段 3：关系录入（婚姻与亲子）

```bash
genea union add --db family.db --type marriage \
  --member "<夫ID>:husband,<妻ID>:wife" --start "光绪十二年"
```

- **正配 / 妾 / 继配**分别建结合（`marriage` / `concubinage` / `remarriage`），
  不归并——谱上「侧室」也是人，后代都挂着。
- **亲子挂靠原则**：孩子只挂「夫妻双方齐全」的结合。孩子该记正室还是侧室，
  是谱学判断，程序不替谱师决定（GEDCOM 往返也不丢这个结构）。

## 阶段 4：一致性校验（每阶段末都跑）

```bash
genea io validate --db family.db        # error 退出码 1，可当门禁
```

| 级别 | 处理策略 |
|---|---|
| error | 必改。出生晚于卒年、父母指向自己、世系有环、冗余父母链找不到结合 |
| warning | 逐条确认。同名同生年（重复录入？）、母亲逾 55 / 父亲逾 80 生育、墓葬早于卒年、排行断号 |
| info | 普查时处理。无公历生年、性别未登记、日期有原文换算不出 |

> 时间类规则只认公历年份：农历原文换算不出就跳过（R12 单独提示），
> **宁可少报，不可拿不可靠的年份去判悖论**。

## 阶段 5：字辈核对（谱的气质在这一步）

```bash
genea poem check --db family.db --lineage <ID>
```

- 每代人名应含本代辈字；辈字所在代与 `generation_no` 一致。
- 不一致的两种命运：**录错了代**（改人物）或**派语记错了**（改派语）——
  先问族老，再动数据。

## 阶段 6：世系、五服与称谓（成谱的内容）

```bash
genea person relation --db family.db <甲ID> <乙ID>
# 关系路径 / 辈分差 / 世代序号 / 五服（丧服等级与月数）/ 称谓（书面/口语）
```

- **辈分一律看关系路径，不看世代序号**——外亲姻亲序号会塌到始祖辈。
- 五服与称谓按明清定型规则集（`shared/rules/*.json`，可换规则数据不改代码）。
- 立谱传、定服制段落时，以这里的输出为准。

## 阶段 7：迁徙与支派（可选，但有价值的维度）

```bash
genea branch add --db family.db --lineage <ID> --name 东八房 --gen-char 明
genea migration add --db family.db --subject-type person --subject <ID> \
  --from <故里ID> --to <新邑ID> --reason 营商 --route "中湘 → 洞庭 → 渝州"
```

Web UI 的迁徙地图按地点经纬度画箭头（自绘 SVG，离线可用）；没坐标的地点
进「待补坐标」清单，后补不影响记录本身。

## 阶段 8：交付与备份

```bash
genea db backup --db family.db --out backup/        # 每次会话结束都做
genea io export gedcom --db family.db --out 交付.ged --submitter 谱师
genea io export tree --db family.db --person <始祖ID> --tree-format mermaid --out 世系.mmd
```

- **GEDCOM 交付**：与其他谱牒软件互操作；自家格式往返零损失（测试保证），
  妾与继配用扩展标签保留，别的软件忽略而不读错。
- **世系图交付**：DOT（喂 graphviz 出图）或 Mermaid（直接贴 Markdown）；
  节点标识是人物 ID、标签才是姓名，同名同姓不会并点。SVG 需 graphviz
  管线，属展示层，暂以 DOT 代替（API 对 svg 明确 501）。
- **备份纪律**：会话结束即备份；大批量导入前必备份；备份目录同步到另一盘。

## 常见坑（都是踩过的）

| 坑 | 规避 |
|---|---|
| 拿世代序号当辈分 | 辈分看关系路径；序号只做字辈/统计 |
| 年号岁首陷阱 | 光绪三十四年冬月初一 = 1908-11-24（不在宣统）；`date era` 只解到年 |
| 同名合并 | R5 报「同名同生年」时先确认是同一人误录两条，还是同名的两个人 |
| 备份=文件拷贝 | 直接 cp 正在写的库会拷到半提交状态；用 `db backup`（VACUUM INTO） |
| 恢复覆盖活库 | 目标已存在默认拒盖；确认要覆盖用 `--force`（旧库移 .bak，不删） |
| 日期编圆 | 解不出就留原文；谱的可信度比「字段完整」值钱 |

## 一页流程总览

```
筹备（收谱/访谈/定派语）
  → 建档（宗族/地点/派语）
  → 人物（先直系后旁支，原文照录）
  → 关系（婚姻分类，亲子挂齐）
  → 校验（error 清零，warning 逐条确认）
  → 字辈（poem check）
  → 世系/五服/称谓（relation）
  → 迁徙（可选）
  → 交付（GEDCOM/世系图）+ 备份（会话末）
```
