### 【高-2】CLI `cmd_bench` 分派位于 try 块之外，异常导致 std::terminate
- **位置**：`cli/src/main.cpp:1012-1014`（try 块起于 1022）

- **修正建议**：把 bench 分派移入 try 块（注意它必须先于「缺子命令」检查，保持第三轮新-C12 的修复语义）。

### 【高-3】公开历法 API `day_ganzhi`/`solar_term_on` 无入参校验，越界读数组
- **位置**：`core/src/calendar/chinese_calendar.cpp:312,348`；`core/src/calendar/chinese_calendar.cpp:89-95`（`days_from_julian`）
- **问题**：`to_chinese` 有 month/day 范围校验，但这两个公开 API 没有。`days_from_julian` 中 `for(i=1;i<m;++i) doy += kDim[i-1]`，m>13 时越界读 `kDim[12]` 及之后（kDim 仅 12 元素）。

- **影响**：未定义行为/结果错误；越界读取理论上可致崩溃。
- **修正建议**：抽取 `to_chinese` 的民用日期校验为公共函数，在这两个入口同样校验，非法返回哨兵或 Error。
- **证据**：`day_ganzhi` 直接 `dayno_of_civil(date.year, date.month, date.day)`，无校验。

## 三、中（5）

### 【中-1】dry_run 出处迁移去重查询恒不命中，报告失真
- **位置**：`core/src/service/provenance_migration.cpp:107-112,163-166`
- **问题**：`dry_run=true` 且来源未登记时，`ensure_source` 返回空串 `source_id=""`；该空串被绑定进 `CitationFilter.source_id` 等值条件，对正常库（source_id 为 ULID）永不命中，去重失效。
- **触发场景**：对尚未创建 Source 的库跑 dry_run 预演。
- **影响**：预演 `citations_created` 虚高、`deduped` 恒 0，误导迁移规模判断；不写库，不影响真实数据。
- **修正建议**：dry_run 无 source 时去重查询跳过 source_id 过滤（绑定 NULL），或用稳定虚拟 ID。
- **证据**：`source_id = "";` 后 `cf.source_id = source_id;`。

### 【中-2】GUI 数值参数 NaN 绕过范围校验，静态转换 UB
- **位置**：`gui/src/main.cpp:34-45`（parse_num）
- **问题**：校验 `v < lo || v > hi` 对 NaN 两比较均 false，NaN 通过；随后 `static_cast<int>(NaN)` 是 UB。
- **触发场景**：`genealogy-gui --width nan`（或任意数值参数传 nan/inf）。
- **影响**：窗口尺寸/字体为未定义值（x86 常为 INT_MIN），窗口创建失败或渲染异常。
- **修正建议**：加 `!std::isfinite(v)` 判定，命中报错退出 2。
- **证据**：`if (... || v < lo || v > hi)` 无 isfinite。

### 【中-3】run_e2e.sh 整文件 CRLF，违反仓库行尾约定
- **位置**：`tools/testdata/run_e2e.sh`（235 CRLF / 0 裸 LF）
- **问题**：`.gitattributes` 要求 `eol=lf`、`.editorconfig` 要求 lf；同目录 build_cases.sh/run_all.sh 均为 LF。
- **触发场景**：Linux/macOS 直接执行（shebang 报 `bad interpreter`；变量带尾随 `\r`）。
- **影响**：CI 若接入该脚本（见高-4）在三平台会失败。本机 Git Bash 实测可跑（77/77），故影响限于类 Unix 环境。
- **修正建议**：转 LF；`git add --renormalize .`；CI 加行尾检查。
- **证据**：字节统计 CRLF=235 bareLF=0。

### 【中-4】vcpkg-install.ps1 残留幽灵 `--overlay-ports` 与硬编码路径
- **位置**：`tools/vcpkg-install.ps1:78`（及头部注释）
- **问题**：`--overlay-ports=D:\cd\tree\genealogy\tools\vcpkg-ports` 指向已删除目录（脚本自己的注释已写明删除）；头部仍称「安装 Drogon 等」、用法示例仍 `drogon:x64-windows`；triplet 路径硬编码开发机绝对路径。
- **触发场景**：按文档在本机运行该脚本装依赖。
- **影响**：vcpkg 对不存在的 overlay 报错或静默忽略，本机安装流程失效；无法在其他机器复用。
- **修正建议**：删该参数，triplet 用 `$PSScriptRoot\vcpkg-triplets` + `$env:VCPKG_ROOT`，更新注释为当前依赖集。
- **证据**：`ls tools/vcpkg-ports` → 不存在；脚本第 78 行仍传该参数。

### 【中-5】build 谱名元数据在 README/手册仍是已裁撤的 lineage 命令
- **位置**：`README.md:14,171,206,253`、`docs/manual/使用手册.md:48,60-61,255`
- **问题**：README 使用示例仍 `genea lineage add`（CLI 顶层只有 `book`，无 `lineage`）；README:253/手册:48 称 build-gui-msvc.bat「构建 core+server+gui」；手册:61 引用不存在的 build-server-msvc.bat 与 `server;gui` feature；手册:255 排障仍提 Web UI/CORS/8080 端口。
- **触发场景**：用户按文档建档/构建/排障。
- **影响**：核心建档示例返回「未知命令: lineage add」(退出码 2)；构建描述与单机定位矛盾。
- **修正建议**：统一改为 `book update`（db init 已建 book 行）、单机两入口、vcpkg `gui` feature；删除 REST/Web 排障行。
- **证据**：`main.cpp` 分派无 lineage；上述文档行。
