# P2 字体度量完善：三处边界的有效收敛（2026-11-23）

## 结论

**回答「还能有效完善么」：能，且收敛到两个真问题，不做过度工程。**

原本两处边界中，「几何模型非字体度量级」的真问题不是缺少字体解析（CJK 全角字体按字符数推进本就是正确模型，引入字体库反而违反依赖纪律），而是**预设 `typography.body_size`（11pt）、CSS 字号（15px）、几何行高（19px）三套数字互不相干**——改预设字号根本不影响产物。本轮把字体度量做成几何与 CSS 的单一来源，并让专名线长线化。core 163 用例 / 993,540 断言，全门禁通过。

## 一、字体度量单一来源

新增 `LayoutGeometry::from_preset(j)`：从预设 `typography.body_size` 推导——
- `body_px = pt × 96/72`（11pt → 15px）
- `body_step = body_px × 1.25` → 19px
- `col_gap = body_px × 1.47` → 22px
- `mark_dx = body_px × 0.93` → 14px
- `note_px = body_px × 0.67` → 10px、`note_step = note_px × 1.2` → 12px

**默认 11pt 时全部回到原视觉数值，零回归**；改预设字号后 CSS 字号、行距、列距、专名线偏移同步联动。

- 渲染器 CSS 不再硬编码 `.body{font-size:15px}`，改为从 `geo.body_px`/`geo.note_px` 生成；标题字号也从字号推导。
- 新增 `geometry_for_preset(id)`：分页器与渲染器共用同一几何。CLI `export layout` 与 `export book --use-layout` 的分页都改用它。
- 新增 `--body-size 22pt` 覆盖参数：无需改 JSON 重建即可微调字号（端到端实测 11pt→15px、22pt→29px）。

## 二、专名线长线化

覆盖层从「每字一段短竖线」改为**按列合并成一条长竖线**，跨列补折线连接。竖线上下伸出量也从字号推导（`body_px×0.8` / `×0.27`）。测试：100 字专名跨列，path 的 M 命令数从 >100 降到 <30（每列一段+跨列折线）。

## 三、验证

| 项目 | 结果 |
|---|---|
| core 测试 | **163 用例 / 993,540 断言全过**（新增 2 例字号联动、1 例 CSS 来源） |
| 字号联动单测 | 11pt→15/19/12/22/14；22pt→29px 且列容量下降 |
| 端到端 | 11pt 产物 font-size:15px；22pt 产物 font-size:29px |
| 专名线 | 100 字跨列 M 命令 <30，无 text-decoration |
| 全门禁 | 三套单测、e2e 77/77、演练、许可、GUI 无头全过 |

开发中踩坑：`notes.note_size_ratio`（0.6）旧字段语义是「每格字数占比」而非字号比，误用会把夹注字号算成 9px；已改用固定字号比 0.67 并加注说明。

## 边界

- 仍是离散近似：按字符数推进，不做字体字面框（glyph advance）的真实测量。
- 但 CJK 全角字体每字等宽，按字符数推进本就是合适模型；只有混排半角/比例字体时才需更细的度量，当前家谱场景以汉字为主。
- 默认行距系数 1.25/1.47/0.93 是保留原视觉的经验值，非排版学标准；若需严格出版级可再按《古籍排版规范》调参。
- 本记录对应改动尚未提交。
