## 3. 高危问题（3 项）

### H-1｜0007 迁移在非空库上必失败
- **位置**：`shared/schema/0007_single_book.sql:84,111`；`core/src/repository/database.cpp:91`
- **问题**：`database.cpp` 打开即 `PRAGMA foreign_keys=ON`；0007 用 `DROP TABLE person` / `DROP TABLE branch` 重建以去掉 `lineage_id`。在 `foreign_keys=ON` 且子表（`parent_child`、`union_member`、`person_name`、`branch.founder_person_id`、`person` 自引用）非空时，DROP 触发隐式 DELETE 与外键检查，必然 "FOREIGN KEY constraint failed"，迁移回滚。
- **触发场景**：用**已有数据的旧库**升级到单谱单库；空临时库测试恰好通过，未覆盖此路径。
- **影响**：存量谱库升级失败。
- **修正**：迁移期间临时 `PRAGMA foreign_keys=OFF`（事务外设置），按 SQLite 官方 12 步表重建流程执行；补"带数据旧库升级"集成测试。

### H-2｜校验器空 optional 解引用
- **位置**：`core/src/validate/validator.cpp:418` · `check_burial_before_death`
- **问题**：`e.date` 是 `std::optional<GenealogyDate>`，未判空即 `year_of(&*e.date)`，空 optional 解引用为 UB（内层 `d==nullptr` 检查无法挽回）。
- **触发场景**：存在 `type='burial'`、`subject_type='person'` 且 `date IS NULL` 的事件，同时人物有卒年。
- **影响**：校验引擎崩溃或误报。
- **修正**：取 `by` 前加 `if (!e.date) continue;`。

### H-3｜GUI 关库时 worker use-after-free
- **位置**：`gui/src/app.cpp:82-85`
- **问题**：「文件→关闭数据库」先 `session_.close()` 后 `reset_panels_for_switch()`；worker 持有 `DbSession*` 并在后台调用 `s->persons().list_persons(...)`，停线程发生在析构连接之后。
- **触发场景**：树装载或全库校验完成前点"关闭数据库"。
- **影响**：use-after-free / 数据竞争，随机崩溃。
- **修正**：与 `app.cpp:269-270` 打开库路径一致——先 `reset_panels_for_switch()`（内部 join worker），再 `session_.close()`。

### H-4｜GUI 树面板线程对象竞态赋值
- **位置**：`gui/src/panels/tree_panel.cpp:75-77` 与 `tree_panel_state.cpp:66`
- **问题**：`poll()` 在 `running_==true` 时不 join；worker 将 `running_` 置 false 后线程仍 `joinable()`，同帧 `!load_in_flight()` 为真即进入 `begin_load`，对仍 joinable 的 `worker_` 赋值 → `std::thread::operator=` 触发 `std::terminate`。
- **触发场景**：装载在途时修改"展开代数"或切换树根。
- **影响**：进程无预警终止。
- **修正**：`begin_load` 入口先幂等 `stop_worker()` 再建新线程。
