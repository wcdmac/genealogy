# 排版打印 / 世系图展示 / 字体兼容 —— 系统性调研与规划（2026-11-22）

## 前置确认

历法扩充已推送：`688a436`，CI run `45035501037` **三平台全绿**（Windows/Ubuntu/macOS 均 success，e2e 全过），工作树干净。本报告基于该基线，调研全程只读。

## 一、结论

三个主题的共同瓶颈是**字体与许可**，而非渲染算法或数据模型。建议按一条统一主线推进：**先建立"数据 → HTML/CSS（统一字体栈）→ 系统浏览器打印/另存 PDF"的离线出版链路，再在同一 HTML 层实现多体例世系图，最后按需引入 ImGui 交互面板**。理由：一次投入同时解决排版、打印、字体嵌入、跨页续接四类问题，且完全绕开 GPL/LGPL/EPL 依赖。

不建议上来就内嵌重量级 PDF 引擎或 WebView——前者要自研竖排/分页，后者引入专有运行时条款，均非当前最高杠杆。

## 二、现状差距（基于当前源码）

| 维度 | 当前能力 | 差距 |
|---|---|---|
| 打印/出版 | 无。仅 `io export tree` 出 DOT/Mermaid 文本，`export gedcom` 出数据文件 | 无 PDF/纸质成册能力；无分页、页眉页脚、开本、装订线 |
| 世系图 | CLI DOT/Mermaid 静态导出 + GUI 十代树面板（文本缩进式） | 无缩放/聚焦/定位；Mermaid 约 50 节点劣化且怕环；无祖先图/沙漏图/五服图；无欧式/苏式跨页续接 |
| 字体 | GUI 按平台探测系统字体（Win 微软雅黑/宋体、mac 苹方、Linux Noto/文泉驿） | 无随包字体；无生僻字回退策略；无 GSUB/异体字支持；微软雅黑（方正版权）**不可用于商业 PDF**，文泉驿闭源商用需授权 |
| 算法底座 | 世系图快照、BFS 路径、辈分差、五服、称谓、派语、16 条规则已齐备 | 数据层无需重做——三项调研的成果都只是"展示层"，底座可直接复用 |

## 三、可选方案与许可证结论

### 3.1 排版/打印

| 方案 | 许可 | 闭源商用 | 判断 |
|---|---|---|---|
| HTML + 系统浏览器打印（@page / writing-mode:vertical-rl / @font-face） | 无新依赖，paged.js 为 MIT | ✅ | **首选**：零新增二进制依赖，天然 CJK 竖排，天然支持 16 开/A4 与中缝；代价是不能静默批量出 PDF |
| PDFium | BSD-3/Apache-2.0 | ✅ | **次选（阶段三）**：C++ C API，须手动 `FPDFText_LoadFont` 做中文回退、自研竖排矩阵 |
| libHaru | zlib/libpng | ✅ | 仅生成无排版，分页/竖排全自研，不经济 |
| WeasyPrint | 本体 BSD，但依赖 Pango/GDK-Pixbuf(LGPL)/Cairo | ⚠️ | 捆绑触碰禁 LGPL，排除 |
| wkhtmltopdf | LGPL-3 + 归档 + CVE | ❌ | 排除 |
| Prince / iText / Vivliostyle / PoDoFo / MuPDF | 商业或 AGPL/LGPL | ❌ | 排除 |
| Qt 打印体系 | LGPLv3/GPL/商业 | ❌ | 项目禁令，排除 |

### 3.2 世系图展示

| 类型 | 需求特征 | 当前覆盖 |
|---|---|---|
| Pedigree 祖先图 | 2ⁿ 可预测网格，暴露空缺，Ahnentafel 编号 | 无 |
| Descendant 后代图 | 不可预测横向膨胀，含表亲关系 | 树面板部分覆盖 |
| Register 等级式 | 编号叙述、无连线、书册友好 | 无 |
| Hourglass 沙漏图 | 中心一人上下对称，纪念场景 | 无 |
| 五服图 | 九族×五等服制，亲等≠服等，须标出嫁/出嗣 | 算法有、图无 |
| 欧式/苏式 | 横行分格 / 垂珠竖线，五世一图，**跨页重叠一世** | 无 |
| 宝塔式/牒记式/现代式 | 居中层级 / 无连线纯文字 / 表格化 | 无 |

技术选型许可证关键点：
- **Graphviz 现为 EPL-2.0**（旧说 EPL-1.0/CPL 已过时）。EPL 是模块级弱著佐权：原样使用、动态链接、作独立外部进程调用，闭源商用可行但须保留声明与许可全文、改动 Graphviz 本体须开源。**静态链接/vendoring 会扩大义务边界**。不存在 MIT 许可的等价 C++ 重写（libgraphviz/libcgraph/libgvc 全是 EPL）。最干净用法：当外部进程调用，或干脆自生成 SVG 彻底绕开。
- **Mermaid MIT**（但 dagre 布局 >50 节点劣化、maxEdges 500、遇环失败）；**D3 ISC**、**自生成 SVG**（自有代码）均可闭源商用。
- **imgui-node-editor MIT**，可与现有 ImGui 栈零新依赖集成，适合做交互式面板。
- **OGDF/igraph GPL** → 直接排除；**WebView2/CEF** 运行时为专有条款，需法务审阅，不作为首选。

### 3.3 字体

**OFL 1.1 的准确结论**（常见误读很多）：允许闭源商用、随软件捆绑、嵌入 PDF、子集化、销售包含字体的软件；硬约束只有三条——不得单独售卖字体文件；分发字体时随附版权声明与 OFL 全文；修改版不得沿用保留字体名（RFN）。用 OFL 字体生成的文档/图形**不会被传染**。

推荐栈：
- 界面：Source Han Sans SC / Noto Sans CJK SC（OFL 1.1）
- 正文/印刷：Source Han Serif SC（OFL 1.1）；繁体用 TC 子集
- 楷体风格备选：霞鹜文楷 LXGW WenKai（OFL，桌面子集须改名）
- **禁用**：文泉驿（闭源商用需授权）、方正/汉仪/微软雅黑（侵权判例：暴雪案 140 万、汉仪案 200 万）
- 生僻字：Unicode 16.0 汉字约 98,682 个，无单一字体全覆盖；须平台回退（DirectWrite/CoreText/fontconfig）+ 从用户数据反推实际字符集做子集
- ImGui 侧：ImGui 1.92 动态字体系统按需烘焙；`ImFontGlyphRangesBuilder` 从家谱数据反推字集，避免全字集图集过大
- 已知技术风险：**ImGui 的 stb_truetype 不执行 GSUB/GPOS**，异体字、竖排替代字形不会自动生效；老谱字形保真需 HarfBuzz（MIT）预烘焙或 PUA 映射

| 优先级 | 事项 | 解决什么 | 成本 | 依赖风险 |
|---|---|---|---|---|
| **P0** | 字体合规替换：随包思源黑体/宋体 SC 子集 + 第三方声明；移除微软雅黑/文泉驿作为商业出版字体 | 三项共同的字体瓶颈 + 版权风险 | 低 | OFL 义务可控 |

| **P1** | 世系图类型扩展：在 HTML 层生成器支持 pedigree / descendant / register / hourglass / 五服 / 欧苏式，跨页续接按苏式"第五世重叠"范式 | 展示类型缺口 | 中 | 自生成 SVG，无第三方 |
| **P1** | 可读性特性：焦点模式、折叠计数徽章、搜索定位、世代对齐、房支分色、环检测标注 | 大图可读 | 中 | 纯前端逻辑 |

## 五、可执行规划建议

**阶段一（P0，建议立即启动）**
1. 引入 Source Han Sans/Serif SC 地区子集到 `assets/fonts/`，按 OFL 随附版权声明与全文；子集改名规避 RFN。
2. GUI 字体探测优先级改为"随包思源 → 系统回退"，彻底移除微软雅黑用于打印的假设。
3. 新增 CLI `genea io export book`（或 `publish`）：参数 `--template {eu,su,tower,register,pedigree}`、`--paper {a4,16k}`、`--orientation`、`--out <html>`，从 SQLite 取数生成自包含 HTML（字体内嵌 base64 子集），提示用户在浏览器 Ctrl+P 另存 PDF。
4. 验收：生成谱书 HTML 在 Windows/macOS/Linux 三平台浏览器打印预览一致；中文字体不缺字；竖排与页码正确。

**阶段二（P1）**
在 HTML 层补齐多体例世系图与跨页续接；把现有 core 的 `render_tree` 从 DOT/Mermaid 扩展为 SVG 生成器（自有代码，规避 Graphviz EPL）；增加焦点/折叠/定位特性。此阶段不引入任何新二进制依赖。

**阶段三（P2/P3，按需）**
只在用户明确需要"桌面内即时交互图"时做 ImGui 面板；只在需要"静默批量出 PDF"时引入 PDFium。两者都需独立立项与法务复核（字体子集改名、FTL 白名单）。

## 六、边界与最大风险

- 本报告为技术调研与规划，**不是法律意见**；OFL/FTL/EPL 的最终商用边界建议在阶段一落地前做一次法务复核。
- 最大风险是**异体字字形保真**：Unicode 按字符统一，老谱异体多同码位不同字形，而 ImGui 的 stb_truetype 无 GSUB；若不做 HarfBuzz 预烘焙，印刷谱书会出现"字对形不对"。
- 次风险是**跨页续接语义**：欧式/苏式的续接规则不同（苏式第五世重叠），模板实现须以结构特征为准，不能只看体例名称（文献中欧式/苏式命名存在互换）。
- 三平台 CI 已验证历法扩充，但**排版/字体改动尚未实现**，本报告不含任何代码变更。
